# 变更影响面分析（可演进性 / 内外一致 / 安全隔离的子能力）

本文档是 `definition-audit` 的子能力，服务于「维度 6 内外一致 / 维度 9 可演进性 / 维度 10 安全与隔离」在**改动阶段**的落地。审核发现问题只是第一步；改定义时如果不评估影响面与迁移路径，很容易把结构缺陷换成一次隐性的破坏性变更。本文档提供影响面识别、破坏性判定、迁移路径设计、审计与安全复核的方法。

术语沿用主 SKILL.md「术语约定」章节：**被审定义**、**定义单元**（类目 / 字段 / 判据条目 / 枚举值 / 状态之一）、**上层根文档**、**下游使用方**（代码 / 提示词 / 脚本 / 配置 / 其它 skill）、**相邻定义**、**产物**。本文档不绑定任何具体项目或领域。

定位：主 SKILL.md 说明"结构性改动需先经用户确认，且要给出改动影响面"；本文档说明"影响面怎么算、破坏性怎么判、迁移怎么写、安全和审计怎么复核"。仅当审核结论涉及定义单元合并 / 拆分 / 增删 / 判据结构改动 / 语义变更时展开本文档；纯措辞收敛与消歧不在此处理。

## 何时展开本子能力

出现以下任一改动时进入本流程：

- 定义单元的**合并**（多个变一个）或**拆分**（一个变多个）。
- 定义单元的**新增**或**删除**。
- 判据的**收紧**（原本能落 A，改后落不上 A）或**放宽**（原本落不上，改后能落）。
- 术语 / 主表达的**替换**并波及跨文档引用。
- 元字段（版本 / 适用范围枚举 / 生效状态）的结构性调整。
- 对外协议 / 输出 schema 的字段增删或字段语义变化。

## 核心原则

- **改定义等于改契约**：结构性改动一律视为契约变更，必须显式评估破坏性与迁移。
- **先影响面，后动手**：任何合并 / 拆分 / 增删 / 语义变更的动作，先输出影响面清单再改，未确认前不动。
- **收敛而非膨胀**：优先合并 / 下沉 / 复用；只在无法收敛时才新增字段或类目。
- **迁移路径显式**：破坏性变更必须给出下游迁移方式与时间线；不得静默生效。
- **安全优先**：触及敏感字段 / 越权路径 / 隔离边界的改动，走额外的安全复核。
- **审计可追溯**：结构性改动记录版本 / 变更日志 / 迁移记录，改动可回溯。

## 兼容等级与安全标记

变更使用两条独立轴记录：

- **兼容等级 `L0` 至 `L3`**：表示对既有 case、消费者和历史产物的破坏程度。
- **安全标记 `S0 / S1`**：表示是否触及敏感字段、鉴权、隔离、审计或高副作用出口。`S1` 是独立阻断项，不等同于最高兼容等级。

| 兼容等级 | 定义 | 典型改动 | 强制动作 |
| --- | --- | --- | --- |
| L0 非破坏 | 不改变已有定义单元的语义与判据，仅措辞收敛、消歧、补写边界 | 修错别字、消同义混用、补写 `不适用` 段 | 记录到变更日志 |
| L1 兼容扩展 | 新增定义单元 / 新增可选枚举，不影响既有 case 归属 | 新增元字段、扩枚举 | 变更日志 + 版本号递增（次版本）+ 下游可选升级 |
| L2 受控语义变更 | 已有判据收紧或放宽，历史 case 可能改归属，但旧结构仍可读取且下游不必同步升级才能运行 | 阈值或判据条件调整 | 变更日志 + 版本号递增（次版本）+ 归属差异清单 + 迁移评估 + 用户确认 |
| L3 破坏性 | 定义单元合并 / 拆分 / 删除 / 主术语替换 / 主键结构变化 | 合并两个定义单元、拆分一个字段、删除废弃字段 | 变更日志 + 版本号递增（主版本）+ 迁移路径 + 下游同步计划 + 用户确认 |

| 安全标记 | 判定 | 强制动作 |
| --- | --- | --- |
| S0 | 不触及敏感字段、鉴权、隔离、审计或高副作用出口 | 无额外安全动作 |
| S1 | 触及上述任一安全边界，或可能扩大日志、导出、缓存、trace 暴露面 | 安全专项复核 + 显式风险提示 + 用户确认 |

一次改动包含多个兼容等级时按最高等级处理；无论兼容等级为何，只要命中 `S1` 就先完成安全复核。

## 影响面识别流程

### 第 1 步：列出被改动的定义单元

- 定义单元（类目 / 字段 / 判据条目 / 枚举值 / 状态）的具体列表（含改前/改后名称、改前/改后语义）。
- 标注每个单元的兼容等级（L0 ~ L3）和安全标记（S0 / S1）。

### 第 2 步：追依赖

依次找到并列出以下四层依赖：

1. **上层根文档**：改动是否与上层约束一致；不一致要显式声明"如何调解"（改被审定义 or 上层给例外）。若上层根文档为"无"，此层跳过并显式记为"无"。
2. **相邻定义**：同层相邻定义是否引用了本次改动的定义单元 / 术语；引用点逐一列出。
3. **下游使用方**：搜索所有引用了改前名称 / 改前语义的位置（代码 / 提示词 / 脚本 / 配置 / 其它 skill）；每一处标注是否需要同步修改。
4. **产物 / 日志 / 报告 / 数据集**：历史产物是否会因语义变更被误读；是否需要保留兼容读取能力。

### 第 3 步：判定破坏性

对每个改动单元回答以下五问：

- 是否让某历史 case 从"能归位"变成"归不了"？
- 是否让某历史 case 从"归到 A"变成"归到 B"？
- 是否删除了下游使用方正在使用的定义单元？
- 是否让下游按旧语义生成的产物被新语义读取时误解？
- 是否引入需要下游同步升级才能继续正确工作的耦合？

前两问任一为"是"时至少为 L2；后三问任一为"是"时为 L3。若前两问造成旧结构无法读取、历史产物被误解或要求下游同步升级，也升级为 L3。

### 第 4 步：设计迁移路径

L2 必须给出归属差异和迁移评估；L3 必须给出迁移方案，四选一或组合：

- **原地并存**：改前名称 / 改前字段作为别名保留一段时间，标注 `deprecated` 与移除版本。
- **双写双读**：过渡期同时按新旧语义写入 / 读取，数据集或产物二者兼容。
- **切换点**：明确 cut-off 版本 / 时间；之前用旧语义，之后用新语义，中间不混。
- **不迁移，直接切**：仅当下游可控且改动窗口极小时使用；必须显式声明"不提供迁移"并经用户确认。

### 第 5 步：安全与审计复核

只要标记为 S1，追加以下复核：

- **暴露面**：改动前后敏感字段的读、写、日志、导出、缓存、trace 覆盖范围对比；是否引入新的暴露通道。
- **鉴权 / 隔离**：是否改变鉴权路径，是否让本应隔离的数据 / 操作可以互访。
- **审计**：改动是否有记录、是否可追溯、是否需要额外的确认门槛（例：批量迁移前必须的人工确认）。
- **残留风险**：即使按方案执行，仍存的风险显式列出，交由用户决策。

## 输出格式

变更清单：

```markdown
| # | 改动单元 | 改前 | 改后 | 兼容等级 | 安全标记 | 分级依据 | 迁移方式 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | <定义单元名（类目/字段/判据/枚举/状态）> | <旧语义> | <新语义> | L0/L1/L2/L3 | S0/S1 | <五问命中项与安全边界> | <无需迁移/归属差异/原地并存/双写双读/切换点/直接切> |
```

依赖清单：

```markdown
- 上层根文档：<路径#章节 - 一致 / 冲突 - 处理> 或 "无"
- 相邻定义：<路径#章节 - 引用点 - 是否需要同步>
- 下游使用方：<代码 / 提示词 / 脚本 / 配置 / 其它 skill 路径列表 - 每处需同步修改的说明>
- 历史产物：<数据集 / 报告 / 日志 - 是否兼容 / 是否需要迁移>
```

迁移与安全：

```markdown
- 迁移方案：<方案说明 + 时间线 + 版本号>
- 版本记录：<主版本 / 次版本 / 变更日志条目>
- 安全复核：<暴露面对比 / 鉴权 / 隔离 / 审计门槛>
- 残留风险：<即使执行方案后仍保留的风险，含用户决策项>
- 用户确认点：<必须由用户拍板的项>
```

## 判定标准（本子能力出口条件）

改动执行前必须满足：

- 每个改动单元都标注了兼容等级与安全标记，且与五问和安全边界的判定一致。
- 上层 / 相邻 / 下游 / 产物四层依赖均已扫过并列出，未静默跳过任一层。
- L2 变更给出归属差异与迁移评估；L3 变更给出明确迁移方式 + 时间线 + 版本号；未给出时不得进入执行阶段。
- S1 变更完成安全复核，暴露面对比与残留风险显式列出。
- 用户确认点单独列出，未确认前不改。

## 常见误区

- **只看单点，不看链路**：改一个定义单元仅在被审定义里改，忘了改下游使用方，形成"文档写 A、下游走 B"的隐性冲突。
- **语义变化不等于结构破坏**：只改变历史 case 归属但旧结构仍可读取、下游无需同步升级时属 L2；合并、拆分、删除等要求消费者迁移的变更属 L3。
- **删除废弃字段跳过迁移**：`deprecated` 字段仍可能被历史产物引用；直接删属 L3，需迁移。
- **术语替换不追引用**：主术语替换只改被审定义主文档，忘了同步相邻定义与下游使用方（代码 / 提示词 / 脚本 / 配置 / 其它 skill）中的引用，导致长期同义混用。
- **安全影响简单化**：把"敏感字段名不变"当作"安全无风险"；实际暴露面（日志、导出、trace）可能被静默扩大。

## 禁止事项

- 禁止在未列出改动单元与级别的情况下动手改被审定义。
- 禁止把 L2 或 L3 改动记为 L0 或 L1 以规避确认与迁移。
- 禁止对 L3 变更省略迁移路径；"直接切"必须显式声明并经用户确认，不得默认使用。
- 禁止对 S1 变更跳过安全专项；"看起来风险不大"不构成跳过理由。
- 禁止只改被审定义主文档、不追下游使用方引用点。
- 禁止用"未来可能需要"作为新增定义单元的理由；本文档默认反对膨胀式改动。
- 禁止在残留风险未列出的情况下宣布改动完成。
