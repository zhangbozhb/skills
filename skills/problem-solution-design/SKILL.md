# 问题与方案设计

把用户诉求收敛为“要达成什么、现在什么最关键、为什么选这个方案、如何实施和验证”。以可评审、可实施的推荐方案为默认产物：用户需要方案且证据足以支持时，不能只给问题分析或审查结论；信息不足或不应推进时，按第 5 步交付澄清、验证或否决结果。用户明确只问必要性或局部取舍时，给出足以支撑该决定的结论与依据。篇幅可以按请求缩放，目标、机制、证据、取舍和必要边界不能因此省略。

## 高级推理视角与整体原则

以下原则从理解诉求开始，贯穿问题定义、取证、候选生成、审查和验收后的重判。它们决定关注什么、如何解释证据、怎样判断方案的价值；不只在分析受阻时用于扩展候选。具体深度随问题调整，但不能因为流程已走通就默认问题边界、前提和价值排序正确。

1. **目标与关键：让局部工作服务于真实结果。** 区分用户希望获得的结果、衡量结果的指标和采用的手段。先判断问题为何值得解决，再找当前最限制结果的环节；不以工作量、技术难度或局部指标改善代替目标进展。核心目标相对稳定，阶段关注点可以随已验证能力和剩余差距变化。
2. **第一性原理与因果：从必要条件和实际机制出发。** 将目标、事实、有效约束、惯例与假设分开，检查“必须如此 / 不可能”的依据。既问某个方案为何能产生结果，也问不用它是否仍可达成目标，以及什么证据会推翻当前解释。经验可以提供候选与先验判断，不能自动成为必然性证明。
3. **系统边界与整体：沿因果和影响范围看问题。** 组织分工、模块边界或现成指标不一定就是问题边界。检查上游输入、下游承接、关键依赖和成本承担，识别局部优化是否制造整体损失。分析范围须覆盖影响结论的因素，实施范围仍受本次授权与资源约束；看见范围外影响不等于承诺扩大实施。
4. **演化与反馈：把方案放回变化中的环境。** 判断结论在哪个规模、阶段和时间窗内成立，考虑延迟效应、瓶颈转移以及参与者对方案的反应。方案会改变原有环境，静态测量的收益可能被新的行为或负载抵消；因此既看直接结果，也看后续反馈，给出维持、切换、升级或停止的条件。
5. **价值、激励与权力：看清谁定义成功，谁承担代价。** 区分“事实如何”与“应优先什么”，核对谁受益、谁付出、谁有决定、拒绝或纠正的权利。检查激励是否诱导指标达标却背离目标，是否把风险交给缺少选择权的人；总体收益不能掩盖受影响方的关键损失或越过有效边界。必要时落实为取舍说明、责任、授权、申诉或审计机制。
6. **可证伪与迭代：让判断能够被现实修正。** 将问题定义和推荐看作有适用条件的判断，主动寻找替代解释、反例和反转选择的条件。优先验证高影响未知，依据证据更新判断；既不因沉没成本维护旧方案，也不因尚有任意未知而拒绝收敛。确定性程度须与证据相符，验收也要能发现原定义或机制判断有误。

运用方式：

- 在各阶段以相关原则检视当前判断；遇到边界遗漏、前提冲突、利益不一致或阶段变化时加深分析，不要求每次依次展开六篇分析。
- 视角可以支持**保留、修正或否定**原判断，也可以识别待验证项。无需为证明使用过某个视角而强行改变方案；应能说明它影响了哪个判断及依据。
- 将相关结论落实到问题定义、证据、候选、价值取舍、适用边界或验收条件。只表达影响用户决策的理由，不用抽象术语替代方案，也不要求另写哲学章节。
- 不同视角冲突时，区分事实分歧、价值取舍和时间或范围差异：事实分歧用证据检验，用户持有的价值决定按第 0 步处理；不能靠抽象偏好裁决或绕过安全与授权要求。

## 执行约定

- 输入至少有当前诉求；现状、约束、已有决策和运行证据按决策需要获取。先识别是否存在设计取舍：已有方案仍可因场景变化、对症性争议或成本风险进入设计；范围已明确且没有新取舍的执行任务直接回到原任务。审核已成文的分类、字段或契约规则本身时转交定义审核类能力，评估它们是否解决业务问题仍属本流程。
- 本 skill 不额外授予实施权限。只要求设计时不改正式实现；调查和验证遵循已有授权与环境权限，涉及写入时明确范围。用户已经授权的动作不重复询问。
- 第 0～5 步表达决策依赖，可合并、穿插或在新证据出现后回看；不要求逐步展示。目标未明确、决定性证据不足或候选未通过审查时，不给确定推荐。
- 区分**检查覆盖**与**输出篇幅**：低风险问题可简短回答；高风险、证据冲突或实质取舍须展开依据。不得为形式完整凑候选、补无关信息或重复检查。

## 第 0 步：确定决策与缺失信息

先明确本轮要决定什么、已有信息能支持到哪里，按缺失性质处理：

| 缺失 | 处理 |
| --- | --- |
| 只能由用户决定的目标、价值排序、范围或授权，或只能由用户提供的外部事实，且答案会改变方向 | 先利用已有上下文；仍缺失时说明影响，默认归并为最多 3 个关键问题。暂停依赖它的推荐或动作，继续独立可做的部分；不能归并的独立取舍可分轮询问 |
| 可从文件、指标、文档或实验取得的决定性证据 | 在允许范围内直接调查；暂时无法取得时，给出候选方向、最小验证动作和结果如何改变选型 |
| 不影响选型的细节 | 标注假设、适用条件或待落位项并继续，不作为前置阻塞 |

生产写入、删除、部署、发消息、付费调用、敏感数据访问或权限边界不明确时，检查现有授权；仍不明确则暂停相关动作。仅缺未来执行授权时，先完成设计、影响分析、验收与回退，将确认留到具体动作之前。

## 第 1 步：定义目标与当前关键

问题定义要说明：在什么场景与约束下，谁面临什么现实与目标的差距，为什么值得改变，以及怎样判断差距已被解决。原因解释和候选解法另行验证，不要求先证明根因才能描述问题。形成以下足以支持选型的结果；简单问题可合并为几句话：

1. **问题与影响**：谁在什么场景遇到什么可观察问题，触发条件、影响范围、不做代价和已有兜底是什么。剥离预设解法与未验证归因；问题反复出现时，按第 2 步追查因果。
2. **核心目标**：写明目标状态、成功判据和验证方式。判据可用数值、行为或覆盖范围；精确数值暂缺但不影响选型时不阻塞。反向检查“判据达成后，用户原诉求是否真的得到满足”。
3. **当前关键**：结合场景、阶段、已验证能力和剩余差距，定位最限制目标达成的环节或关键未知，给出依据和优先投入。不要把最显眼、最难或最熟悉的问题自动当作关键。
4. **约束与取舍**：记录项目、资源和安全边界、价值排序、本次范围；涉及多个角色时说明谁受益、谁承担成本及谁能决定。关键约束注明来源、适用条件与可变性；既有架构或做法不因“当前如此”就成为不可变红线。

**回读校验**：比较原诉求与问题复述的主体、核心动作及对象，校验语义而非要求字面一致。“准确判断任务完成”不等于“任务及时停止”；关键词重叠不能证明语义一致。每个新增动作或对象应能解释它与原目标的关系；无依据的替换须撤回。引入新目标或改变问题类型时说明依据并回显供纠偏，需要用户决定的目标变化按第 0 步处理。默认内部完成校验，不固定输出逐词映射。

**主次与边界**：围绕一个主要决策组织分析；共同服务于目标的正确性、效率等判据可以并存，存在因果或依赖关系的子问题可以一起规划，并写明依赖与先后顺序。可独立决策的问题分别处理或列为明确的后续候选，不混成无主次的目标。与本次目标无关的事项说明排除理由，不自动许诺后续建设。

**边界复核**：按整体原则检查当前定义是否漏掉关键依赖、受影响角色或时间范围，指标达标是否仍可能使真实结果变差。必要时提出分析边界或成功判据的修正，说明它与原诉求的关系；涉及用户目标、价值排序或实施范围变化时按第 0 步处理。不能靠把后果划为“范围外”来判定问题已经解决。

### 聚焦当前关键与动态校准

- **让投入对准目标**：每项主要调查或计划动作要能解释它缩小哪个目标差距、影响哪个选型判断，或满足哪项必要约束。自查“即使把这一点做到很好，整体结果会明显改善吗？”优先处理高影响且可干预的环节；必要的安全和隔离检查不能因暂非瓶颈而省略。
- **随阶段调整**：无可行路径时，关键可能是可行性；已有办法且在目标场景验证后，关键可能转为效率、质量、成本或可靠性。复用仍适用的证据，保留已有能力与质量底线；演示或小样本成功不等于目标场景可行。
- **变化后重判**：新证据、规模或资源变化、旧瓶颈解除时，检查原判断的适用条件，更新关注点、候选排序、计划及受影响的验证项。说明“什么变了 → 为什么重点变了 → 计划如何调整”，只重查受影响部分。不得为追逐局部指标擅自改变核心目标、价值排序或降低成功判据。

判断问题是否值得解决：依据影响、发生频率或预期风险、机会收益、不做代价和现有兜底，区分值得推进、暂不必要与证据不足。尚未发生的风险可以基于可信机制和影响证据评估，不要求先造成损失；纯粹“未来可能用到”不能证明建设必要性。

若仍无法去除预设方案、区分目标与手段、定位当前关键、拆解因果或选择调查方法，按具体卡点读取 [references/problem-definition.md](references/problem-definition.md)，不再运行一遍完整流程。进入选型前至少能说明目标与判据、当前关键及依据、关键约束和范围；尚缺的决定性信息按第 0 步处理，不要求问题定义完整后才允许取证。

## 第 2 步：取证与检验关键前提

围绕最可能改变决策的未知取证，默认先复用用户提供且适用的指标、输出和已确认决策。技术问题按需读取仓库约束、相关入口、相邻实现、测试和配置；非技术问题使用相应流程、角色、规则和实际数据。不为完整性遍历无关材料。

关键判断区分：

- **事实**：由文件路径、命令输出、指标、复现或用户明确确认的事实支撑，注明来源与适用范围。用户给出的原因猜测仍是假设，模型的一般知识不能冒充项目现状。
- **推断**：由事实支持的解释，说明主要依据及什么证据会推翻它。
- **待验证**：尚无充分依据的前提，不作为确定选型的基础。

证据要求：

- 强度匹配风险。生产、安全、跨模块契约或不可逆变更的关键事实至少用两处独立证据交叉核验；同一来源的重复转述不算独立。用户偏好和价值排序以用户决定为准。
- 有冲突时比较来源、时间、范围和复现条件；无法解释的冲突标为待验证。估算写依据及区间，不把理论值写成实测。
- 文件、命令或环境不可用时，记录缺失及已覆盖范围；没有项目材料不虚构现状，也不证明“绝对不存在”。
- 不回显凭证、真实用户数据或其它敏感内容；证据引用只保留判断所需信息。

### 证据是否足以选型

- **决定性缺口**：依据已有事实，在合理的不同取值或解释下会改变可行性、候选选择或风险接受性。先消除该缺口再确定推荐；没有证据支持的无限可能性不构成持续调查的理由。
- **非决定性未知**：在有依据的范围内不会改变选择，或可在既定约束内处理的落地细节。说明为何不阻塞、在哪个范围内成立，以及越界后何时重判。
- **实施验收**：选型依据充分后，回归、监测和验收列入计划；不能声称尚未执行的验收已经通过，也不能把决定可行性的未知仅改名为“上线后验证”。

例：不同方案的成本相差数倍，精确报价的小幅浮动可能不影响选择；未知的线程安全性可能使并发方案不可行，须先验证。原型与接口证据已支持选型时，完整回归仍需执行，但无需先完成正式实现才能给设计建议。

对每个关键结论保留最小证据关联：`结论 → 来源与适用范围 → 状态 → 对选型的影响`，可直接融入正文，不强制另建表。最小验证须写明要区分的前提、动作与范围、成本、预期观察及选型门槛；记录已执行动作的结果，未执行明确写明，避免把验证计划当成证据。

### 关键前提检验（第一性原理）

将全局的第一性原理与可证伪原则用于当前证据。尤其当“必须如此、只有这条路、必然发生、不可能做到”等判断限制候选或决定取舍时，执行以下检验；没有出现这些措辞也应留意隐含的必要条件：

1. 拆出结论依赖的前提，区分已证实事实、有效约束、现行惯例与待验证假设。当前做法只证明现状，不能证明它是唯一做法。
2. 回到目标所必需的条件，检查惯例或假设是否真是必要条件；寻找满足目标与有效约束的反例、替代路径或成立条件。不得擅自解除约束，也不得把“没找到反例”视为必然成立。
3. 用最小证据或验证判断“在给定条件下成立 / 被反例推翻 / 仍待验证”，据此保留约束、修正候选或安排验证。未验证的替代路径不能直接视为可行。

规划中呈现影响决策的前提及依据，用“目标真正需要什么条件”“什么事实说明现有做法不可替代”帮助用户检视。可调查项直接取证，只向用户询问其持有且会改变方向的信息。证据已足以决策时停止，不重证可靠事实或把思考提示变成固定问卷。

### 因果追查与停止条件

问题复发、表层修复失效或方案依赖某个原因解释时，沿证据追查可干预的因果链，区分症状、诱因与持续产生问题的机制。对拟定原因做干预或反事实检查：“改变该因素后，在相同条件下现象是否消失、减轻或仍出现？”结合复现、代码或过程证据排除替代解释；只观察到症状减轻不足以确认根因。

| 当前证据支持到哪里 | 可以作出的判断与下一步 |
| --- | --- |
| 只解释了相关性或触发因素 | 仍是因果假设；若影响选型，继续取证，不能直接命名为根因 |
| 支持某个持续产出问题的机制，且改动能消除机制或切断传播路径 | 在说明适用条件和剩余原因后据此设计；验证改动是否实现该效果，不要求证明唯一根因或保证永不复发 |
| 仅降低频率、减轻后果或增加兜底，产生问题的机制仍在 | 说明尚未解决的部分；若因此未达到最终目标，按显式缓解处理，不能声称根因已消除 |

追查在证据足以支持当前决策、外因不可控且传播边界已查清，或现有证据耗尽时收敛，并注明停止理由。外因不可控时仍检查隔离和降低暴露能否满足目标；证据耗尽且原因决定选型时，返回最小验证。需要先止血时可使用已有证据支持的缓解办法，不必等待穷尽根因，但须遵守第 4 步的缓解条件。

## 第 3 步：生成有实质差异的候选

先检查更轻的路径，不把新增机制当作默认答案：

| 方向 | 检查问题 |
| --- | --- |
| 不做 | 现有行为与兜底是否已满足目标，改变的收益是否值得投入？ |
| 删除 | 去掉冗余或错误职责能否消除目标差距？ |
| 合并 | 合并重复逻辑、职责或流程能否减少分歧与维护成本？ |
| 复用 | 现有模块、工具、配置或流程是否可直接或小幅调整后覆盖？ |
| 回滚 | 回到已验证状态能否更快恢复目标，兼容性与数据代价是什么？ |
| 约定替代 | 文档、配置或流程约定能否可靠达到同一目标；依赖人工遵守的成本是否可接受？ |

在内部覆盖这些方向，输出只保留影响选型的结论；不适用项无需逐项留痕。已有方案被验证且仍适用时，将其作为比较基线；没有任何更轻方案成立时，说明具体差距。

- 优先找能满足目标的最小改动方案；找不到时说明具体障碍，不为满足数量要求虚构候选。
- 没有实质取舍时一个候选即可；有取舍时通常比较 2～3 个。区分用户提出的候选做法与明确指定的硬约束：前者可以比较替代方案，后者未经同意不能解除。证据表明限定做法不对症或代价不合理时，说明依据并给出边界内方案或可供用户决定的约束调整。
- 初筛候选只需写清**机制、目标贡献、关键前提、主要代价与差异**。按审查需要补充运行、风险和失败处理细节；问 1 已淘汰或待验证的候选不展开完整实施计划，最终推荐方案再补齐具体改动、依赖顺序和回退。
- 候选要在同一目标、负载或适用场景、约束和时间窗下比较。说明“牺牲什么、换来什么”，同时考虑立即与延迟、局部与整体影响；适用前提不同则分场景推荐，不能把条件差异伪装成优劣。
- 不为无证据的未来需求新增抽象、模块或字段；“最小改动”也要计入维护、故障与迁移代价，不能只比较改动行数。

用整体原则检查候选空间是否被现有做法过早限定：是否可以改变介入环节、切断因果链、调整流程或激励，而非只替换技术实现。候选趋同时回看边界和前提；原方案仍最好也可以保留，不为体现视角而凑新候选。

## 第 4 步：八问审查与决策状态

先审问 1；不对症则淘汰，决定性证据不足则待验证。只有问 1 通过的候选才须继续覆盖问 2～8；低风险项可简判，冲突或决定性未知须展开，不要求每个维度都写独立章节。任意阶段发现明确安全红线均应立即处理，不必等待问 7。

| 问题 | 判定要求 |
| --- | --- |
| 1. 对症性 | 机制与证据足以支持候选在既定范围内达到成功判据，能消除、绕开或缓解当前关键障碍。必要前置工作可属于实施计划，但只完成它不能算最终方案；用户明确只要求该阶段时按其判据评估并标明最终目标尚未完成 |
| 2. 必要性 | 不做的代价或机会收益成立，且没有足够的更轻替代；有则优先该替代 |
| 3. 通用性 | 特例局部处理；有共同机制与实际需求才做通用建设，避免过度泛化 |
| 4. 复杂度 | 新概念、状态、分支和维护约定是否可控，复杂度会如何扩散；高复杂度须由明确收益、更轻方案不能满足目标的依据及可行回退或补偿共同支撑 |
| 5. ROI | 当前时间窗内的收益能否覆盖开发、回归、维护、故障、迁移及挤占关键投入的机会成本；可用定性或区间，不强行货币化。低收益须说明仍值得做、缺少等效更轻替代及可回退或补偿的依据；证据支持净负则淘汰 |
| 6. 一致性 | 与有效约束、用户决策、架构、术语、接口及职责一致；必要的架构或流程调整须说明兼容与迁移方式，不能因不同于现状就直接淘汰 |
| 7. 安全与隔离 | 核对敏感数据流向、鉴权、用户或租户隔离、权限及高副作用入口的变化，按风险设置控制、审计与验证；无法降至可接受的风险直接淘汰，收益不能抵消红线 |
| 8. 整体净效应 | 目标达成后没有把问题隐蔽转移给下游、他人或未来；比较影响范围、严重度、概率和可恢复性，确认新增后果没有抵消整体收益，不按问题数量计净效应。存在未解决部分时区分已认可的范围外事项与显式缓解 |

问 1 检查是否达成本次目标，问 5 比较投入产出，问 8 检查问题是否被转移或产生新的整体后果。三者可引用相同证据，但不能用“本模块更快、开发成本低”替代对下游及长期影响的判断。非货币收益、避免的损失和必须履行的要求应纳入比较；不能用局部 ROI 跳过安全或其它有效约束。八问负责检查候选，不能替代对问题定义的审视；发现指标失真、边界遗漏或反馈导致目标落空时，回到第 1 步校准，不能只调整审查措辞。

### 显式缓解

需要先止血或暂时接受未解决影响时，同时保留最终目标与本次缓解判据。用户已认可该阶段范围和代价时，问 1 按缓解判据检查，问 8 仍检查全局后果；不得把达到缓解判据宣称为最终目标完成。尚未认可且该取舍必须由用户决定时，可给出具体建议并按第 0 步暂停相关决定。正常分阶段实施不自动等于缓解；只要未借阶段交付掩盖未满足的目标或接受额外代价，就按既定阶段验收。

缓解方案必须记录可检索债务：**为何走此捷径**（放弃什么、换得什么）、**当前上限**（在哪些条件或规模内有效）、**升级触发条件**（何时必须采用更完整方案）。三项不全、风险不可接受或整体得不偿失时不能推荐；普通范围外事项不自动视为债务。

### 统一判定

| 状态 | 条件与下一步 |
| --- | --- |
| 通过 | 八问均有足以支持当前决策的依据，无未解决的决定性缺口；可进入推荐，尚未执行的验收留在实施计划 |
| 待验证 | 任一决定性前提缺证或冲突未解；保留候选与验证门槛，暂停其确定推荐，继续评估其它候选 |
| 待修正 | 已知冲突可以通过明确改动修正；修正后重查问 1 和受影响维度，修正前不算通过 |
| 淘汰 | 不对症、不必要、过度泛化、净收益为负、无法合理修正的有效约束冲突或风险不可接受等有充分依据；记录原因，不循环包装到通过 |

**停止与复查**：推荐候选自身仍有决定性缺口时，必须补证或走验证出口，不能用“验证太贵”判为通过。已有候选通过后，只对其它方向中有具体依据可能改变选择、且验证价值覆盖成本的未知继续取证；否则说明范围与未覆盖项并收敛，不宣称全局最优。修正候选或环境变化后只复查问 1 与受影响维度；没有新证据或机制改变时，不循环修改同一淘汰方案。没有候选通过时，区分证据不足与有充分依据的否决，不能强推“最不差”的方案。

## 第 5 步：收敛与交付

选择与当前决策相符的出口；不同子问题可以各自有状态，但整体结论不得掩盖决定性阻塞：

| 出口 | 条件 | 必须交付 |
| --- | --- | --- |
| 推荐方案 | 候选通过且足以支持取舍 | 推荐、目标与当前关键、机制、关键改动、实施顺序、验收与回退、主要取舍及限制 |
| 验证 | 缺决定性证据且可通过调查消除 | 当前倾向及成立前提、已有证据与缺口、已执行动作及结果（未执行写明）、下一最小动作及成本、结果如何影响选型；不能只列调查项 |
| 澄清 | 缺只能由用户决定或提供的关键输入 | 当前目标与已知结论、哪项缺失为何改变方向、最少问题，以及已能完成的独立部分 |
| 否决 | 证据足以说明暂不必要或已评估候选均不值得推进 | 目标、否决范围与依据、候选淘汰原因、现有兜底或替代、重新评估条件；不把有限候选失败写成问题不可能解决，也不强加无价值验证 |

输出先给决定及直接理由，再补足读者评审所需的信息：

- **简短评估**：仅在用户明确只问必要性或局部取舍时，说明结论、目标关联、决定性证据和适用条件；有后续动作再说明验证或回退。若用户要方案，即使要求简短，也须把适用的设计、实施和验收内容说清，不能以“建议优化，后续验证”代替方案。
- **完整方案**：按下列骨架展开；允许合并章节，不要求固定篇幅比例。技术方案尽量落到真实模块、接口或配置，非技术方案落到角色、流程、规则和治理。已知重要字段不能因追求简短省略；无关字段可省略，相关但未知的字段须标明并判断是否阻塞。
- **审查呈现**：问 1 的结论和依据必须可见；其它已评估维度展示影响取舍的结论，高风险或用户要求完整审查时逐问给出。低风险项可合并说明，不重复证据；问 1 未通过的候选标明后续未评估。不得把“没有展示”当成“无需检查”。

```markdown
## 推荐与理由

<选什么，通过什么机制达到目标，为什么现在选它>

## 目标与边界

- 当前差距与成功判据：<适用场景、目标状态、验证方式>
- 当前关键：<最限制结果的环节及证据>
- 约束与范围：<必须保持的底线、解决与不解决的事项、主要取舍>

## 方案设计

- 解决机制：<改动如何产生目标结果>
- 关键改动与复用：<模块/接口/角色/流程/规则，复用什么，改变什么职责或边界>
- 运行方式：<主流程、状态变化、调用或数据流；非技术方案说明交接与决策方式>
- 失败处理：<关键失败的检测、恢复或降级，相关数据与用户影响>

## 实施计划

1. <可执行步骤、依赖、影响范围、交付物、必要确认点；优先作用于当前关键>
2. <后续步骤；区分本次必需与可选项>

## 验收与回退

- 验收：<对应成功判据的用例或指标、边界与失败场景、观察窗口、通过门槛；适用时观察下游影响与行为反馈>
- 回退或补偿：<触发条件、具体操作、恢复状态及不能恢复的部分>

## 取舍与限制

- 候选比较与审查：<问 1 结论和依据，其它影响选择的审查结论，不选其它候选的原因>
- 残留风险与未知：<证据范围、非决定性未知及不阻塞的理由>
- 重判条件：<什么新证据或场景变化会改变重点与方案>
- 显式缓解债务：<适用时记录：为何走此捷径 / 当前上限 / 升级触发条件>
```

可回退的方案说明如何恢复；无法完全回退时如实说明不可恢复部分、损失上限与补偿措施，涉及不可逆取舍按第 0 步处理，不虚构“一键回滚”。材料不可用但非决定性时可以保留待落位项；决定性前提仍未知时使用验证出口，不能以“条件化推荐”绕过闸口。

### 受阻时如何继续

| 情况 | 处理与出口 |
| --- | --- |
| 文件、命令、权限或环境不可用 | 记录失败与覆盖范围，先用已有证据或允许的替代来源；足以选型则继续，否则说明下一最小验证，不虚构已调查的现状 |
| 证据冲突或验证结果不能区分候选 | 不选择更有利于原判断的一条；检查来源、适用条件或验证设计，补充有区分力的证据。仍不确定则保持待验证 |
| 多个阻塞同时存在 | 按依赖处理；能独立调查的先调查，只有用户持有的关键输入才询问。已确认的候选可继续细化，但受阻结论不能写成通过 |
| 所有候选都失败 | 已知冲突可修正则修正并复查；证据缺口走验证；有充分否决依据则交付带范围的否决，不无限生成近似候选 |

## 交付前自查

- 目标与判据仍对应用户诉求，当前关键有依据，主要投入能推进目标或满足必要约束。
- 已用相关整体原则检视问题边界、隐含前提、反馈与利益影响；结论有依据，不因视角未改变方案就判为无效，也不以局部指标替代真实结果。
- 决定性事实、推断与待验证项没有混写，已确认能力的证据仍覆盖当前场景。
- 声称消除根因、切断传播或只做缓解的程度与证据相符，未把相关性或症状减轻当作根因证明。
- 推荐通过八问；没有将局部改善、前置工作或显式缓解冒充最终目标完成。
- 用户得到与请求深度匹配的决定、具体方案或可推进的验证动作；方案含适用的机制、运行与失败处理、实施和验收，验证有结果记录及选型门槛。
- 授权、风险、回退和残留债务已在适用处处理，没有把敏感信息写入输出。
