# 一盏茶 / 一杯咖啡研究

帮助用户快速建立“足以继续思考、讨论或做低风险判断”的可靠认知。默认以 10-15 分钟研究努力和 5-15 分钟阅读预算为双重约束；工具延迟不可控时，查询与来源上限优先于墙钟时间。

本 skill 不承诺全面覆盖或专家水平。复杂对象应缩小覆盖范围，不能通过降低证据标准来维持广度。

执行主线：准入判断 → 冻结研究契约 → 选择路径（使用意图 × Topic 形态 × 知识起点模式）→ 最多三轮自适应取证 → 达到最小充分证据即停 → 按意图与形态输出自包含简报。

## 成功标准

一次合格的快速研究应让读者能够：

- 用一句话复述研究对象、边界和核心结论
- 解释关键机制、比较维度或主要路线
- 区分直接证据、多源综合、推断和未确认内容
- 说明结论的适用条件、例外与残余不确定性
- 判断当前简报是否够用，以及何时需要升级研究

## 第 0 步：准入判断

先判断请求是否适合快速研究，再选择复杂度。以下任一情况成立时，不进入 L1-L3：

- 用户需要医疗、法律、财务、安全等高风险场景的个体化建议或最终决策
- 任务要求系统综述、正式尽调、投资报告、可发表研究或完整竞品矩阵
- 结论必须依赖访谈、观察、实验、内部数据或其它尚未取得的一手证据
- 用户只需核验一个事实、数字、定义或版本；此时直接做定点核验
- 用户实际要求代码审查、缺陷定位、代码修改或工具实现

不适合时说明快速扫描能确认什么、不能确认什么，并转交到合适的研究或执行类型。不要把高风险、证据不足或超出范围的请求包装成“复杂度更高的快速研究”。

## 研究契约

开始前在内部冻结以下信息。仅当缺失会改变研究方向或造成明显风险时，提出一个决定性问题；其余使用默认值并继续。

| 要素 | 默认值与处理规则 |
| --- | --- |
| 研究对象 | 用户给出的领域、概念、问题、事件、方法或比较主题 |
| 使用意图 | 默认“理解”；也可为“比较”或“低风险判断” |
| 目标读者 | 聪明但没有该领域背景的从业者 |
| 知识起点模式 | 默认“从零理解”；也可为“基于现有材料”或“仅指定来源” |
| 读后能力 | 能复述核心机制、关键证据和边界 |
| 对象边界 | 当前、全球；主题天然包含地区或场景时从主题推断 |
| 时间范围 | 当前有效信息；时效敏感时明确起止时间或截止日期 |
| 阅读预算 | 普通速览约 5 分钟；“一杯咖啡”默认 10-15 分钟 |
| 证据条件 | 默认可使用公开资料；用户材料和本地项目按实际可访问范围处理 |
| 交付形式 | 中文、自包含、关键判断可追溯 |

“最新”“当前”“近期”必须转换为具体截止日期或时间范围。用户指定资料时先读取该资料，再决定是否需要外部补充，不重新从零搜索。

### 用户材料的证据角色

不要把用户提供或项目中出现的所有内容都当成事实。按以下角色使用：

- **约定事实**：用户明确指定为本次范围、规则或 source of truth
- **待核验输入**：用户观点、AI 草稿、未确认文档或二手材料
- **直接证据**：能证明当前代码行为、测试结果、数据或正式规则的一手材料
- **背景材料**：只帮助理解语境，不单独支撑关键结论

知识起点模式决定如何使用这些材料：

- **从零理解**：不使用项目材料推断读者已经掌握什么
- **基于现有材料**：以用户确认过的材料校准解释起点，并补充缺口
- **仅指定来源**：不扩展到用户未指定的材料或外部来源

文件中出现某个概念，只能证明读者可能接触过，不能证明已经理解或认同。项目代码只能证明当前实现，不能单独证明平台契约、用户需求或普遍规律。若读者无法访问外链或原始材料，正文必须包含理解结论所需的定义、上下文和证据摘要。

## 选择研究路径

### 使用意图

使用意图决定简报要帮助读者完成什么：

| 意图 | 核心产物 |
| --- | --- |
| 理解 | 心智模型（具体类比起步）、关键机制、关键术语、常见误解、复述检查 |
| 比较 | 统一比较维度、差异、取舍、适用条件 |
| 低风险判断 | 判断、依据、反例、成立条件、残余风险 |

“理解”意图面向零背景读者时，按“具体类比 → 关键机制 → 协同工作流或实例”展开：类比建立直觉，机制只保留支撑多数行为的少数关键项，再用一个工作流或实例展示它们如何协同。类比和讲法可由模型组织，但被解释的机制、事实和边界仍须满足下文证据要求，不能用未核验的模型解释代替取证。

产品、服务或系统设计前置研究属于上述意图之一，不单独成为模式。相关时补充角色、任务、工作流、交接物、激励、规则和失败场景；桌面研究只能生成设计假设，不能替代真实用户证据。

### Topic 形态

Topic 形态只描述研究对象和证据任务，不承担风险准入：

| 形态 | 判定特征 | 组织方式 | 查询上限 | 深读来源上限 |
| --- | --- | --- | ---: | ---: |
| L1 聚焦 | 一个主问题，边界清楚，证据相对稳定 | 答案链：结论 → 机制 → 依据 → 例外 | 4 | 3 |
| L2 关联 | 2-4 个相关子问题、比较维度或因果环节 | 问题树：拆分 → 分支取证 → 汇合 | 7 | 5 |
| L3 领域 | 多对象、参与者、层级或路线 | 主干地图：边界 → 对象 → 流程 → 路线 → 争议 | 10 | 6 |

查询和来源数量是上限，不是配额。处于两个形态之间时选择较高一级；范围过宽时优先收窄到最能服务使用意图的主问题。

读者是新手不会自动提高 topic 形态。应通过减少覆盖范围、补充最小前置知识和降低术语密度来适配。

### 轻量覆盖矩阵

L2/L3 在内部维护覆盖矩阵，不写文件、不向用户展示完整过程：

```text
核心问题或维度 | 所需证据 | 状态
```

状态使用 `待覆盖 / 已覆盖 / 未确认`。L2 覆盖已选的 2-4 个分支；L3 只选择与使用意图有关的主干维度。矩阵用于发现关键缺口和判断何时停止，不要求所有可能维度都被填满。

## 自适应取证循环

取证最多执行三轮。任一轮达到“最小充分证据”即可停止，不为完成形式继续搜索。

### 1. 锚定

确认问题表述、专业词汇、时间范围和最直接的起始来源：

- 优先读取用户指定材料和当前项目中的相关一手材料
- 外部研究优先官方文档、标准、监管材料、原始研究、财报或原始数据
- 技术主题优先官方文档、原始仓库、测试和基准
- 记录后续检索必须使用的术语，不急于写结论

稳定且低争议的描述性事实可在本轮直接结束取证，具体证据要求见“最低证据要求”。

### 2. 补缺

围绕尚未回答的核心问题补充来源：

- L1 追查机制、适用条件和必要例外
- L2 分别回答各分支，再检查分支之间的因果、依赖或取舍
- L3 补齐边界、对象、流程、参与者、路线、约束和变化中的必要项
- 材料驱动任务采用“结论 → 原始证据位置 → 解释 → 例外”

不要按来源逐篇摘要。只提取会改变领域结构、关键判断或置信度的信息。

### 3. 反证与核验

以下情况必须执行反向查询或独立核验：

- 结论涉及最新变化、比较、排名、数字、政策或版本
- 来源存在利益关系、相互转载或定义不一致
- 判断存在争议、影响较大，或将支持低风险决策
- 当前结论主要来自综合分析而非直接证据

比较局限、失败、替代解释和反例。来源冲突时比较定义、样本、时间、覆盖范围和利益关系；无法消解就保留分歧。

## 来源与证据规则

### 逐项匹配来源

不要只按 A/B/C 给整个来源定级。对每条关键判断检查：

- **直接性**：来源是否直接观察或定义该事实
- **权威性**：来源是否有资格说明该问题
- **时效性**：发布时间和适用版本是否满足时间范围
- **独立性**：多个来源是否真正独立，而非相互转载

高质量综述、专业机构和主流专业媒体适合建立结构；从业者文章、社区讨论和评论适合发现实践语言、摩擦和待验证假设。

### 最低证据要求

- 稳定、低争议的描述性事实：一个直接一手来源可以充分
- 时效、比较、争议或利益相关判断：至少两个独立来源
- 数字、日期、政策、版本和“最新”判断：回到原始数据或官方材料核验
- 实践信号不能单独支撑高影响事实
- 只引用本次实际读取或用户提供的来源，不编造标题、作者、数字或 URL

### 关键判断标记

只对会影响理解或行动的关键判断标记，不给每句话加标签：

| 证据状态 | 含义 |
| --- | --- |
| 直接证据 | 一手材料直接支持 |
| 多源综合 | 两个或以上独立来源共同支持 |
| 推断 | 基于已知证据的解释，仍可能存在替代解释 |
| 未确认 | 当前证据不足、冲突或不可访问 |

关键判断同时标注 `高 / 中 / 低` 置信度，并用一句话说明理由。置信度取决于上述四个维度加来源一致性，不取决于措辞是否肯定。

### 关键判断到来源的映射

“比较”和“低风险判断”意图必须在内部建立轻量映射；“理解”意图仅在存在争议或关键推断时使用：

```text
C1 关键判断 → S1 直接证据 + S2 独立验证
C2 关键判断 → S3 多源综合
```

映射只覆盖关键判断。最终简报可用行内链接或 `[S1]` 标记保持可追溯，不输出冗长审计表。

## 停止与完成状态

以下任一条件成立时停止搜索：

- 核心问题已有最小充分证据，新增来源只重复现有判断
- 连续两个高质量来源没有增加新维度或改变置信度
- 查询或来源上限已用尽
- 公开证据不足、材料不可访问或冲突无法在预算内消解

停止时记录一个标准原因：

| 停止原因 | 含义 |
| --- | --- |
| `evidence-sufficient` | 已达到最小充分证据 |
| `budget-exhausted` | 查询或来源预算已用尽 |
| `evidence-thin` | 公开证据不足以支持核心判断 |
| `source-unavailable` | 必要来源或用户材料不可访问 |
| `conflict-unresolved` | 来源冲突无法在预算内消解 |
| `out-of-scope` | 请求未通过快速研究准入 |

输出必须给出一种完成状态：

| 状态 | 使用条件 |
| --- | --- |
| 充分 | 核心问题得到回答，关键判断达到相应证据要求 |
| 部分完成 | 已形成可用主干，但仍有非阻塞缺口 |
| 证据不足 | 核心判断缺少直接或独立证据，不能可靠回答 |
| 已升级 | 请求超出快速研究边界，已说明后续研究类型 |

状态使用规则：

- 状态是完成度而非质量分数
- `已升级` 只用于第 0 步准入失败，不分配 L1-L3
- 部分完成、证据不足和已升级都必须说明停止原因与下一安全动作
- 停止原因为 `source-unavailable` 或 `evidence-thin` 时，优先请求用户提供可信 URL、指定材料或可访问的一手来源，不用模型知识补齐

## 综合与输出

输出一份符合阅读预算的自包含简报。结构由使用意图和 topic 形态共同决定，不机械填满所有章节。

```markdown
# [研究对象]：一盏茶 / 一杯咖啡简报

> 使用意图：[理解 / 比较 / 低风险判断]
> 目标读者：[知识起点]
> 知识起点模式：[从零理解 / 基于现有材料 / 仅指定来源]
> 时间范围：[起止时间 / 截止日期]
> 阅读预算：[约 N 分钟]
> Topic 形态：[L1 / L2 / L3]
> 本次覆盖：[覆盖与不覆盖]
> 完成状态：[充分 / 部分完成 / 证据不足]
> 停止原因：[标准停止原因]

## 30 秒结论
[一句话定义、边界和核心结论]
- [关键判断]（证据状态；置信度 + 理由）

## [心智模型 / 比较框架 / 判断依据]
[按使用意图选择主体结构]

## 关键术语（按需）
| 术语 | 通俗解释 | 为什么重要 |
| --- | --- | --- |

## 边界、反例与未确认项
- [成立条件、替代解释、争议或证据缺口]

## 合上文档后应记住的 3 件事
1. [...]
2. [...]
3. [...]

## 复述检查（仅“理解”意图）
1. [由浅入深的实战场景题，用于自测]
2. [...]
3. [...]
> 可提示读者：作答后我可指出漏洞并用追问引导，而非直接给标准答案。

## 下一步
- **已经够用，如果**： [...]
- **应升级研究，如果**： [...]
- **下一安全动作**： [...]

## 来源
- [来源标题](URL) — 角色；发布日期/版本；支撑什么
```

未通过准入判断时，不使用上述模板，不分配 Topic 形态，改用：

```markdown
# 快速研究边界说明

> 完成状态：已升级
> 停止原因：out-of-scope

## 当前能确认什么
[仅陈述已有充分证据支持的内容]

## 当前不能确认什么
[说明证据、授权或研究方法缺口]

## 下一安全动作
[建议的研究或执行类型]
```

执行约束：

- 约 5 分钟阅读预算：正文通常 800-1,500 个中文字
- 约 10-15 分钟阅读预算：正文通常 2,000-4,000 个中文字
- 读者背景越弱，覆盖范围越窄；不得删除必要解释以维持主题广度
- 来源列表记录发布日期、版本或访问日期中与时效判断相关的信息
- 用户只要求口头速览时，压缩为“30 秒结论 + 主体结构 + 下一安全动作”
- 用户要求保存文件时再写文件；默认直接在对话中交付

## 后续追问适配

同一对话中的追问继承已确认的研究契约，不重新从零研究：

| 用户反馈 | 后续处理 |
| --- | --- |
| 没看懂、概念混乱 | 降低抽象度，补充具体例子，不继续增加概念 |
| 想知道如何应用 | 保留证据边界，切换到“比较”或“低风险判断”意图；可让用户带真实任务作为背景 |
| 想练习或被考 | 出由浅入深的场景题，不直接给答案，作答后指出漏洞并追问引导 |
| 提出具体疑问 | 优先回答该疑问，再决定是否扩展主干 |
| 已经掌握基础 | 减少基础说明，提高信息密度 |
| 提供新材料 | 判断其证据角色，只补充受影响的判断 |

用户明确说“重新研究”或更换 topic 时，才重新冻结研究契约。

## 升级路径

- 错误代价较高、需要多轮三角验证、反方审查或正式报告：使用桌面深度研究能力
- 市场规模、竞争格局和正式行业报告：咨询或市场研究
- 产品机会、假设和实验顺序：产品发现
- 访谈、可用性测试、问卷或研究运营：用户研究
- 单个事实、数字、定义或版本：定点核验

只有对应 skill 当前可用时才调用具体名称，不把外部 skill 名称写成硬依赖。

## 自检

输出前检查：

- 准入判断是否先于 L1-L3，且没有把高风险请求当作高复杂度处理
- 使用意图、知识起点模式、读后能力、时间范围、阅读预算和证据条件是否明确
- Topic 形态、查询上限和输出组织是否一致
- L2/L3 覆盖矩阵是否只包含关键维度，并暴露了阻塞缺口
- 是否达到最小充分证据后及时停止，没有机械跑满三轮
- 来源要求是否与判断风险匹配，没有机械要求所有事实双重来源
- 关键判断是否标明证据状态、置信度和理由
- 比较或低风险判断是否建立了关键判断到来源的映射
- 是否区分用户约定事实、直接证据、待核验输入和背景材料
- 完成状态、标准停止原因和下一安全动作是否明确
- 设计前置研究是否把桌面资料结论误写成真实用户证据
- “理解”意图面向零背景读者时，是否用具体类比起步并聚焦少数关键机制，且类比未替代取证
- 简报是否自包含，并能在目标阅读预算内读完
