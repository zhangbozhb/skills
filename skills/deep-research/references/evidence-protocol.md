# 证据与主张协议

本文件规定深度研究中如何把来源转化为可审计主张。它不规定必须搜索多少次，而规定什么证据足以支持什么强度的结论。

## 基本单位

使用四种对象，不把“来源多”误当成“证据强”：

- **研究问题**：本次最终要回答的问题
- **关键主张**：会改变读者理解、比较、建议或行动的陈述
- **证据片段**：来源中直接支持、限制或反驳某条主张的内容
- **来源**：证据片段所在的原始材料及其生产背景

主张按角色分为：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 描述 | 对对象、规则、状态或事件的陈述 | 某版本支持某功能 |
| 比较 | 在共同口径下比较两个或以上对象 | A 在相同测试中快于 B |
| 因果 | 声称 X 导致或影响 Y | 政策变化导致成本上升 |
| 预测 | 对未来状态或概率的判断 | 需求将在一年内增长 |
| 规范 | 关于应当如何的价值或规则判断 | 应优先保护隐私 |
| 建议 | 结合用户目标提出的条件式行动 | 在约束 C 下选择 A |

比较、因果、预测和建议比稳定描述需要更强证据。建议不能通过“多引用几篇文章”自动成立，必须显式连接用户目标、约束和取舍。

## 来源记录

为每个实际读取的来源分配 `S01`、`S02` 等稳定编号。至少记录：

```text
id:
title:
author_or_org:
url_or_locator:
published_or_updated:
accessed:
source_type:
primary_or_secondary:
independence_group:
scope_and_method:
supports:
challenges:
limitations:
```

记录规则：

- `published_or_updated` 使用与当前性判断有关的日期；没有日期就写未知
- `source_type` 使用官方文档、法规、原始研究、原始数据、财报、标准、代码、专业综述、媒体、专家评论、社区实践等可理解类别
- `independence_group` 标记共同公告、共同数据集、同一作者团队、转载链或资助关系
- `scope_and_method` 只写解释证据适用范围所需的信息
- `supports` 和 `challenges` 指向主张编号，不写与本研究无关的长摘要
- 无法访问正文、只看到搜索摘要或他人转述时，不登记为已读证据来源
- 来源 ID 标识实际读取的材料版本，不仅是 URL。仅迁址或证据内容未变时沿用 ID 并记录新定位；影响主张的正文、数据或版本已修订时，保留旧记录，为已读新版本分配新 ID，并在局限中标注修订关系。无法取得旧原文时注明无法复核，不用新内容回填旧证据。
- 同一材料的不同版本默认属于同一独立组，不能因新 ID 增加独立来源计数；相关主张须区分版本适用范围，再决定沿用、修正或降低置信度。

来源是“一手”不代表自动可靠。公司官网能直接证明公司如何描述自己，不能单独证明产品效果；法规原文能证明条文，不能单独证明执行效果；原始研究能证明该研究的结果，不能自动外推到其它样本。

## 主张记录

为关键主张分配 `C01`、`C02` 等编号：

```text
id:
claim:
importance: pivotal | supporting | context
claim_type:
scope:
supporting_evidence:
challenging_evidence:
evidence_state:
confidence:
confidence_reason:
conditions:
unresolved:
```

`evidence_state` 使用：

| 状态 | 判据 |
| --- | --- |
| 直接支持 | 适用的一手材料直接定义、观察或测量该主张 |
| 独立汇合 | 两个或以上独立证据链在共同口径下支持 |
| 有限推断 | 证据支持部分前提，结论仍依赖分析或外推 |
| 存在争议 | 高质量来源在相关口径下得出冲突结论 |
| 未获支持 | 当前没有足够证据，或证据只来自搜索摘要/转述 |

不要给报告里的每一句话建账。优先记录：

- 执行摘要中的结论
- 比较表中的决定性差异
- 精确数字、排名、首次、最佳和“当前”判断
- 因果、预测和建议
- 受到强反例挑战的主张

## 来源质量

来源质量按主张逐项判断，不给整个网站永久评级：

1. **直接性**：来源是否直接观察、定义或测量该主张
2. **方法适配**：方法、样本、比较条件是否能回答当前问题
3. **权威性**：作者或机构是否有资格说明该类事实
4. **时效性**：日期、版本和适用期是否满足研究契约
5. **独立性**：是否形成新的证据链，而非重复传播
6. **透明度**：是否披露数据、方法、假设和限制
7. **利益关系**：是否存在可能影响陈述的商业、政治或学术激励
8. **可核验性**：关键数字、引语和方法能否追溯

来源选择优先顺序通常是：

```text
原始规则/数据/研究/代码
  -> 高质量独立复核或综述
  -> 专业机构与专业媒体
  -> 专家或从业者分析
  -> 社区讨论与线索
```

这不是固定排名。用户体验、实施摩擦和失败模式可能需要社区与实践来源，但此类来源不能独自证明总体发生率或普遍因果。

## 最低证据门槛

根据主张的重要性和失败代价设门槛：

| 主张 | 最低要求 |
| --- | --- |
| 稳定、低争议的定义或功能 | 一个当前、适用且直接的一手来源 |
| 日期、版本、政策条文、财务数字 | 原始记录或官方材料；必要时核对修订状态 |
| 当前状态、趋势或变化 | 当前一手来源 + 一个独立核验；明确截至日期 |
| 比较、排名、最佳或领先 | 共同定义和测试条件 + 至少两个独立证据链 |
| 争议性事实或利益相关方主张 | 直接来源 + 独立复核 + 反方证据搜索 |
| 因果主张 | 时间顺序、机制和替代解释审查；优先因果设计或多方法证据 |
| 预测 | 可解释模型/假设、基准情景、敏感性和失效条件 |
| 高影响建议 | 已核验事实 + 用户目标/约束 + 选项比较 + 风险与回退条件 |

如果领域不存在理想证据，不降低门槛后假装满足。保留主张，但把状态降为“有限推断”“存在争议”或“未获支持”，并说明缺少什么。

## 独立性

“三个链接”可能只有一个证据源。以下情况通常不独立：

- 多家媒体转载同一新闻稿、采访或通讯社稿件
- 多篇文章引用同一数据集或同一研究，但没有独立分析
- 同一作者或机构在不同渠道重复发布
- 供应商材料、合作伙伴案例和受资助报告共享利益关系
- 聚合站、AI 摘要和搜索结果复述原文

独立性可以来自不同数据、不同方法、不同作者团队、不同利益位置或独立复核。主张账本中按证据链计数，不按 URL 计数。

## 冲突处理

发现冲突后，建立最小冲突表：

| 项目 | 来源 A | 来源 B | 是否可调和 |
| --- | --- | --- | --- |
| 定义/指标 |  |  |  |
| 对象/样本 |  |  |  |
| 方法/比较条件 |  |  |  |
| 时间/版本 |  |  |  |
| 地区/场景 |  |  |  |
| 利益关系 |  |  |  |

处理顺序：

1. 先确认是否在回答同一个问题
2. 回到原始数据、规则或研究核对转述
3. 检查更新、勘误、撤回和版本变更
4. 判断差异是否来自样本、方法或适用条件
5. 能分条件成立时，写成条件化结论
6. 仍无法消解时，保留争议并降低置信度

不得用来源数量投票，不得平均不同口径的数字，不得只呈现支持预期结论的一方。

## 置信度

置信度是主张级判断，不是报告的统一分数：

- **高**：证据直接、方法适配、当前有效，达到该类主张的最低证据门槛，且没有未处理的强反证；需要独立核验的主张还须满足独立性要求
- **中**：核心方向有支持，但存在外推、方法限制、时间差或未完全消解的次要冲突
- **低**：证据间接、样本薄弱、来源不独立、当前性不足或有强替代解释

置信度理由必须说明最主要的支持与限制。不要把“官方来源”自动等同于高置信度，也不要用小数分数制造精确感。

## 数字、日期与引语

### 数字

每个会影响结论的数字至少核对：

- 原始出处与发布日期
- 指标定义、分母、单位和币种
- 名义值还是实际值，存量还是流量
- 时间窗口、样本和地区
- 是否由研究者换算；如有，写出计算方式
- 不同对象是否在同一口径下可比

### 日期与版本

- “当前”“最新”“近期”写成具体截至日期
- 软件、政策、标准和数据注明版本或适用期
- 旧来源继续使用时，说明为什么仍有效
- 发布日期、更新日期、事件发生日期不要混用

### 引语

- 只使用在原文中逐字核对过的引语
- 保留必要上下文，不通过截断改变原意
- 无法核对原文时改为释义，并标明来源观点
- 翻译引语时说明为译文；有歧义时保留原文关键词

## 引用规则

- 引用放在它实际支持的主张附近，不只在段末堆一组链接
- 一个引用不应覆盖它没有证明的整段内容
- 二手来源引用一手材料时，关键主张尽量回到一手材料
- 来源列表说明每个来源在研究中的角色，不只列标题和 URL
- 同一来源支持多条主张时可以复用，但不能把复用误写为独立验证
- 用户无法访问来源时，正文仍应包含理解结论所需的证据摘要
- 不编造作者、标题、日期、页码、DOI、数字、引语或 URL

## 搜索与深读

查询围绕证据缺口生成，不围绕主题无限扩散。常见查询角度：

- 官方术语、标准名、版本号和原始文件名
- 核心主张的正向与反向表述
- `limitations`、`failure`、`criticism`、`retraction`、`errata`
- 不同角色会使用的术语、缩写和语言
- 精确数字 + 原始数据发布机构
- 论文标题/DOI/作者 + dataset/code/supplement
- 产品/项目 + changelog/issues/security/advisory

深读来源时先回答：

1. 它实际声称了什么？
2. 它凭什么声称？
3. 证据适用于谁、什么时间和什么条件？
4. 哪些内容是作者解释而非直接结果？
5. 哪个限制最可能改变本研究的使用方式？

停止阅读一个来源的条件是：已经提取与当前主张有关的证据、方法、范围和局限，而不是把全文摘要完。

## 交付前证据审计

逐条检查 pivotal claims：

- 主张文字是否比来源更强
- 是否至少有一个直接证据锚点
- 需要独立核验时是否真的独立
- 反证和冲突是否记录
- 截至日期和版本是否满足契约
- 数字、引语和比较口径是否可复算或可定位
- 推断是否显式，是否存在未说明的替代解释
- 置信度是否由证据决定，而非由措辞决定

任一项失败时，补证据、缩小适用范围、降低主张强度或标为未获支持。不要通过删除所有不确定内容制造一份看似完整的报告。
