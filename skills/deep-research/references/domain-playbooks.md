## 通用用法

对每个领域先确定：

1. 哪类来源有资格定义对象或直接观察事实
2. 哪类来源适合独立核验、解释机制或暴露失败
3. 该领域最常见的口径错位和利益冲突
4. 哪些结论需要一手研究、实验或专业判断，桌面资料无法证明

每个分支使用“来源梯度”，不要只依赖一种来源：

```text
定义/原始事实锚点
  -> 独立复核或高质量综合
  -> 实践、失败与利益相关方视角
  -> 反证和更新检查
```

## 学术与文献研究

### 来源梯度

1. 同行评审论文、正式会议/期刊记录、原始数据和补充材料
2. 预印本、作者稿、注册报告和研究协议
3. 系统综述、Meta 分析、高质量叙述综述
4. 学术数据库记录、引用网络、作者与机构主页
5. 新闻稿、博客和媒体解释，仅用于发现或解释背景

### 建图

- 把研究问题拆成对象、干预/暴露、比较、结果、场景和时间
- 区分奠基研究、当前代表研究、相反结果和方法学批评
- 记录检索数据库、查询式、日期范围、纳入/排除条件
- 只有执行了可复核协议和系统筛选，才能称为“系统综述”

### 深读

- 核对研究设计、样本、基线、测量方法、效应量和不确定区间
- 区分主要终点、次要终点、事后分析和探索性发现
- 检查统计显著性与实际意义是否一致
- 查看数据、代码、补充材料、勘误、撤回和后续复现
- 追踪引用链时同时向前找后续研究、向后找原始依据

### 常见陷阱

- 用引用量、期刊名或作者声望代替方法审查
- 把预印本和同行评审论文混为同等成熟度
- 把单个样本的结果外推到不同人群或环境
- 只综述支持某理论的研究，忽略发表偏倚和空结果
- 把观察相关写成因果，把模型指标写成现实效果
- 用综述中的转述代替核对被引用的原始研究

## 技术、软件与开源项目

### 来源梯度

1. 官方文档、规范、版本记录、仓库代码、测试和发布产物
2. 维护者 issue、PR、设计文档、安全公告和基准脚本
3. 可复现的独立基准、生产案例和技术分析
4. 社区 issue、论坛和问答，用于实施摩擦与失败模式
5. 教程和聚合文章，只用于发现术语与入口

### 建图

- 冻结版本、运行环境、目标工作负载和评价指标
- 分开研究能力、架构、运维、生态、成本、安全和成熟度
- 区分“文档声称支持”“代码存在”“测试验证”和“生产可用”
- 比较前统一硬件、数据、参数、缓存、并发和测量方法

### 深读

- 从 README/官方文档定位公开契约，再用代码和测试核对实现
- 查看 changelog、release、弃用计划和兼容矩阵
- 对 bug 和限制同时搜索 open/closed issues、修复 PR 和受影响版本
- 基准必须读取方法，而不是只抄排行榜数字
- 安全主张回到公告、CVE、补丁和受影响版本

### 常见陷阱

- 用星标、下载量或营销 benchmark 直接代表质量
- 比较不同版本、硬件、数据集或优化级别的性能数字
- 把示例代码当成完整生产实践
- 只看当前文档，不检查旧版本行为或迁移成本
- 看到配置项就假设代码实际使用了它
- 把社区 workaround 写成官方保证

## 产品与服务比较

### 来源梯度

1. 官方文档、合同条款、定价页、SLA、隐私与安全文件
2. 官方 changelog、状态页、支持政策和产品演示
3. 独立测评、采购材料、审计/认证记录和可复现测试
4. 客户案例、用户评论、社区讨论和迁移复盘
5. 营销内容和联盟内容，仅作为供应商主张

### 建图

- 先从用户任务和约束定义比较维度，不从供应商功能表复制维度
- 区分必须项、偏好项、排除项和未来项
- 记录计费单位、合同期、使用量假设和隐藏迁移成本
- 功能、可靠性、安全、集成、支持、退出成本分别取证

### 深读

- 对关键功能核对文档、计划版本、地区和套餐限制
- 对价格建立可复算情景，不只比较标价
- 对可靠性查看 SLA 定义、免责条款、状态历史和独立经历
- 对案例注明是否由供应商选择、是否可代表目标场景
- 将“没有公开证据”与“没有该能力”分开

### 常见陷阱

- 把功能数量当作适用性
- 把免费试用体验外推到规模化运维
- 用供应商案例证明普遍效果
- 忽略数据迁移、锁定、培训、治理和退出成本
- 评分网站的样本、激励和时间范围不透明

## 公司、市场与行业

### 来源梯度

1. 监管披露、审计财报、公司注册记录、招股书和官方统计
2. 行业协会、政府数据、交易/采购数据和方法透明的数据库
3. 公司公告、投资者材料和管理层访谈
4. 专业媒体、研究机构和分析师报告
5. 招聘、专利、网站流量、应用排名和社区信号等代理指标

### 建图

- 明确市场定义、价值链、地区、客户群和时间
- 分开市场规模、增长、份额、盈利、竞争位置和能力判断
- 对公司主张建立“自报 -> 原始记录 -> 独立核验”链
- 代理指标只能回答其直接观测的现象，不自动等于收入、用户或需求

### 深读

- 财务数字核对会计期、币种、GAAP/非 GAAP、合并范围和重述
- 市场规模核对 top-down/bottom-up 方法、纳入对象和基准年
- 交易、融资和估值区分宣布、签约、交割与推测
- 多家公司比较时统一年度、业务口径和地区
- 对关键管理层陈述搜索后续兑现、修订和相反数据

### 常见陷阱

- 把 TAM、SAM、SOM 或不同市场定义混在一起
- 用融资额、估值、流量或招聘量直接代表经营质量
- 把公司公告和媒体转载计为多个独立来源
- 忽略幸存者偏差、未披露公司和数据库覆盖偏差
- 跳过“不确定字段”后生成过于肯定的尽调报告

## 政策、法规与标准

### 来源梯度

1. 法律法规原文、正式标准、法院/监管决定和政府公报
2. 官方实施指南、咨询文件、解释、FAQ 和执法记录
3. 立法历史、影响评估、技术报告和公开数据
4. 专业法律/政策分析、学术研究和利益相关方意见
5. 媒体报道与评论，用于事件线索和公共争议

### 建图

- 区分提案、草案、通过、发布、生效、过渡期和实际执法
- 明确法域、适用主体、豁免、责任、处罚和申诉路径
- 分开“条文要求”“监管解释”“实践执行”和“社会效果”
- 涉及个案时只说明一般规则与需要专业判断的变量

### 深读

- 引用当前有效原文，并检查修订、废止和生效日期
- 对政策效果寻找实施数据、评估方法和替代解释
- 对跨法域比较先建立共同概念，不直接类比术语
- 记录官方解释与法院/监管决定是否一致
- 高风险结论明确“研究信息，不构成个案法律意见”

### 常见陷阱

- 把新闻宣布写成已经生效的规则
- 用法条文本直接证明执行效果
- 忽略地方规则、例外、过渡期和执法裁量
- 把不同法域同名概念视为相同制度
- 二手解读过期，但未回到现行原文

## 新闻、事件与历史演变

### 来源梯度

1. 原始文件、讲话、数据、影像、记录和当事方声明
2. 现场报道、通讯社和具有更正机制的专业媒体
3. 独立调查、档案、学术历史研究和事实核查
4. 评论、回忆录和社交媒体，用于视角与线索

### 建图

- 建立事件时间线，区分发生、首次报道、确认和后续修正
- 分开“已确认事实”“当事方声称”“媒体解释”和“研究推断”
- 记录信息是否来自同一匿名消息源或同一现场材料
- 当前事件采用滚动截至时间，交付前复查重大更新

### 常见陷阱

- 多家媒体复述同一消息源却被当作独立确认
- 早期报道在后续被修正，但旧数字继续传播
- 时间顺序错误导致因果误判
- 当事方陈述被写成客观事实
- 事后资料改变了当时参与者可获得的信息集

## 设计与用户工作流

### 来源梯度

1. 已有一手用户研究、观察、访谈、支持记录和真实工作产物
2. 产品使用数据、流程数据和实验结果
3. 行业流程、岗位规范、系统规则和领域专家材料
4. 案例、社区讨论、竞品和桌面研究

### 建图

除领域知识外，至少覆盖：

- 角色与谁为结果负责
- 触发任务的事件和待完成工作
- 当前流程、工具、输入、输出与交接物
- 决策点、权限、规则和约束
- 频率、时限、认知负担和协作成本
- 激励、规避行为、替代方案和非使用原因
- 正常路径、边界场景、失败恢复和异常升级

### 证据边界

- 项目代码只能证明当前实现，不能证明用户需要
- 工单和社区帖子能暴露问题类型，不能直接证明总体发生率
- 竞品功能能证明市场上存在某种方案，不能证明它适合目标用户
- 领域专家描述不能替代真实用户在真实环境中的行为
- 桌面研究产出的是设计假设、招募方向和研究问题，不是已验证需求

### 常见陷阱

- 以内部流程为中心，而非用户任务和结果
- 只研究理想主流程，不看交接、例外和恢复
- 把用户“说想要”直接等同于会使用或愿意付费
- 用高频抱怨代替样本和情境分析
- 研究了界面功能，却没有研究权限、激励和组织规则

## 跨语言与地区研究

- 为同一概念建立本地语言、英文、缩写和旧称查询词
- 关键制度、产品和组织优先查当地官方来源
- 翻译术语时保留原文，避免把近似概念强行对齐
- 比较地区数据时核对统计定义、报告周期和覆盖范围
- 注意本地搜索生态、访问限制和媒体转载链
- 机器翻译只能帮助发现和初读；关键引语与高影响条文需要核对原文
- 某语言资料缺失不等于该地区没有事实或实践，报告中应说明覆盖偏差
